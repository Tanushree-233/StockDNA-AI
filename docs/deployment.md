# StockDNA-AI: Free Public Deployment Guide & Specification

This document details the public deployment architecture, platform selection, configuration manifests, and operating procedures for **StockDNA-AI**.

---

## 1. Selected Hosting Provider: Render (Web Service Free Tier)

### Why Render Was Selected
After evaluating Google Cloud Run, Firebase App Hosting, Hugging Face Spaces, and Render:
1. **Unified Application Support**: Render natively builds both the Node.js/Vite frontend and the Python/FastAPI/XGBoost backend into a single unified web service using one standard build command.
2. **True Zero-Cost Free Tier**: 750 free instance hours per month, 512 MB RAM, and 0.1 CPU allocation with no credit card required for standard signups.
3. **Automatic Public HTTPS**: Instantly provisions a free TLS/SSL certificate and public URL:
   `https://stockdna-ai.onrender.com` (or user-chosen service slug).
4. **Direct GitHub Continuous Deployment**: Automatically triggers fresh builds whenever commits are pushed to the `main` branch of `https://github.com/Tanushree-233/StockDNA-AI`.
5. **Infrastructure as Code**: Supports declarative deployment via [`render.yaml`](file:///c:/Users/OM%20MORE/Documents/GitHub/StockDNA-AI/render.yaml) blueprint.

## 2. Free-Tier Availability & Cold-Start Notice

> [!IMPORTANT]
> **Free-Tier Inactivity & Cold Starts**:
> The application is publicly accessible, but the free hosting tier may scale down when idle after 15 minutes of inactivity. The first request after inactivity may experience a cold-start delay of approximately **30 to 50 seconds** while the container/runtime warms up. Subsequent requests respond with standard low latency.

The system is **NOT** claimed to have 24/7 uninterrupted uptime without cold starts on the free tier. This is standard operational behavior for zero-cost academic cloud hosting.

## 4. Build and Start Commands

- **Build Command**:
  ```bash
  cd frontend && npm install && npm run build && cd .. && pip install -r requirements.txt
  ```
  *Explanation*: First compiles the React SPA into static assets in `frontend/dist/`, then installs backend Python dependencies (`fastapi`, `xgboost`, `shap`, `scikit-learn`, `uvicorn`).

- **Start Command**:
  ```bash
  python -m uvicorn backend.app:app --host 0.0.0.0 --port $PORT
  ```
  *Explanation*: Runs Uvicorn binding to the dynamic `$PORT` injected by the hosting environment, serving both the API routers and the static frontend mounted at `/`.

## 5. Required Environment Variables

| Variable Name | Required | Default / Description |
|---|---|---|
| `APP_ENV` | Yes | `production` |
| `PORT` | Yes | Injected automatically by Render (e.g. `10000`) |
| `JWT_SECRET_KEY` | Yes | Secure random 32-byte key (generated by Render via `generateValue: true`) |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | No | `120` (Token validity duration) |
| `DATABASE_URL` | No | `sqlite:///./stockdna.db` (Defaults to local SQLite) |
| `CORS_ORIGINS` | No | `*` (or specific production domain `https://<service>.onrender.com`) |

## 6. Database & Persistence Behavior

1. **Default Ephemeral Storage**: On the Render free tier, the filesystem is ephemeral across container restarts or new deployments. Users can register, log in, run predictions, and query their prediction history during the active lifecycle of the instance.
2. **Optional Permanent Database**: For long-term permanent history storage across months of idle sleeping, a free managed PostgreSQL instance (e.g. Render Free PostgreSQL, Neon, or Supabase) can be connected by simply setting the `DATABASE_URL` environment variable.

## 7. Step-by-Step Deployment Instructions

### Method A: Declarative Deployment via Render Blueprint (Recommended)
1. Push the repository to GitHub:
   ```bash
   git add .
   git commit -m "Prepare StockDNA-AI for public deployment"
   git push origin main
   ```
2. Log in to [Render.com](https://dashboard.render.com).
3. Click **"New +"** &rarr; **"Blueprint"**.
4. Connect the GitHub repository: `Tanushree-233/StockDNA-AI`.
5. Render reads `render.yaml` automatically, provisions the `stockdna-ai` web service, builds the frontend and backend, and publishes the live HTTPS URL.

### Method B: Manual Web Service Setup via Render Dashboard
1. On the Render Dashboard, click **"New +"** &rarr; **"Web Service"**.
2. Select **"Build and deploy from a Git repository"** and select `StockDNA-AI`.
3. Configure settings:
   - **Name**: `stockdna-ai`
   - **Region**: Oregon (US West) or Frankfurt (EU Central)
   - **Branch**: `main`
   - **Runtime**: `Python 3`
   - **Build Command**: `cd frontend && npm install && npm run build && cd .. && pip install -r requirements.txt`
   - **Start Command**: `python -m uvicorn backend.app:app --host 0.0.0.0 --port $PORT`
   - **Plan**: `Free`
4. Under **Environment Variables**, add:
   - `APP_ENV`: `production`
   - `JWT_SECRET_KEY`: *(click Generate for random secret)*
   - `ACCESS_TOKEN_EXPIRE_MINUTES`: `120`
5. Click **"Create Web Service"**.

## 8. Alternative Container Deployment (Google Cloud Run / Docker)

For organizations or evaluators preferring containerized deployment, the multi-stage [`Dockerfile`](file:///c:/Users/OM%20MORE/Documents/GitHub/StockDNA-AI/Dockerfile) is fully configured:

```bash
# Build production Docker container:
docker build -t stockdna-ai .

# Run container locally:
docker run -p 8000:8000 -e JWT_SECRET_KEY=my-local-secret stockdna-ai

# Deploy to Google Cloud Run:
gcloud run deploy stockdna-ai \
    --source . \
    --platform managed \
    --region us-central1 \
    --allow-unauthenticated
```

## 9. Post-Deployment Verification Checklist

Upon deployment, verify the public HTTPS URL:
1. `GET /` &rarr; Loads the React single-page application.
2. `POST /auth/register` & `/auth/login` &rarr; Authenticates user and issues JWT.
3. `POST /predict` (`TCS`) &rarr; Evaluates 34 features, returns BUY/HOLD/SELL and probabilities.
4. `Inspect SHAP` &rarr; Confirms INTERNAL vs EXTERNAL attribution percentages.
5. `GET /datatool/universe` &rarr; Displays tracked equities.
6. `GET /research/metrics` &rarr; Confirms audited out-of-sample metrics.
7. `GET /history/` &rarr; Displays saved prediction under authenticated session.
